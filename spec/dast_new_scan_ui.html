New Scan

Configure a dynamic security scan. Add one identity per role so the engine can test authorization across roles.

1 Target

The engine fingerprints the target (classic site, SPA, or API-only) and adapts automatically.

2 Identities & roles

Add an identity for each role. Multiple roles unlock cross-role authorization testing (BOLA / BFLA) — e.g. can a Viewer reach an Admin function, or User A read User B's data?

🔐
Credentials are never stored. They are held in memory only for the duration of the scan and redacted from all logs. An Anonymous identity (no credentials) is always included as the no-session baseline.
